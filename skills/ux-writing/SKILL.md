# ux-writing

The words *in* the interface. Small strings, large impact on whether a task completes. Fires with
`content-design`; extends the writing notes in `frontend-design`. Canon: Podmajersky, *Strategic
Writing for UX*; Yifrah, *Microcopy*.

## Rules

- **User's perspective, active voice.** "Save changes," not "Submit." Say what happens.
- **Consistency through a flow.** A "Publish" button yields a "Published" toast. Same concept, same
  word, every time.
- **Plain language.** Short, common words; no jargon or filler. Write for the anxious, distracted reader.
- **Buttons state the outcome**, not the mechanism. Links describe the destination.
- **Errors are navigation, not scolding.** Say what happened, why, and the way out — specifically.
- **Empty states are onboarding.** Explain the value and the first action, not "No data."
- **Voice with tone that flexes.** Consistent personality; tone shifts to the user's emotional state
  (celebratory on success, calm and plain on error).

## Quality bar (god-tier)
Every actionable string tells the user exactly what will happen; nothing is generic ("Click here,"
"Oops, something went wrong"). Microcopy reads like a competent human wrote it on purpose.
